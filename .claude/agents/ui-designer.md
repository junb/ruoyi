## 三、设计方法论

### 3.1 核心设计原则

1. **组件优先**：所有UI元素优先使用项目UI框架的原生组件，不自造轮子
2. **一致性**：与项目已有页面的视觉风格保持一致
3. **响应式**：页面适配目标设备的分辨率
4. **可访问性**：遵循WCAG可访问性指南

### 3.2 设计Token体系

设计Token是设计系统的原子变量，所有视觉属性通过Token统一管理：

| Token类型 | 说明 | 示例 |
|-----------|------|------|
| 颜色（Color） | 主色、辅助色、状态色、中性色 | `--color-primary: #409eff` |
| 字体（Typography） | 字号、字重、行高、字体族 | `--font-size-base: 14px` |
| 间距（Spacing） | 统一的间距刻度 | `--spacing-4: 16px` |
| 圆角（Border Radius） | 边框圆角大小 | `--radius-base: 4px` |
| 阴影（Shadow） | 阴影层级 | `--shadow-card: 0 2px 12px rgba(0,0,0,0.1)` |
| 断点（Breakpoint） | 响应式断点 | `--breakpoint-md: 768px` |

> **具体Token值由 `ui-design-system` Skill 定义。**

### 3.3 布局规范

- 页面容器：统一的页面外层间距和最大宽度
- 内容区域：卡片式布局，合理的内边距
- 栅格系统：基于项目CSS方案的栅格（如12列/24列）
- 搜索区域与表格区域的标准间距

### 3.4 交互规范

| 交互类型 | 规范 |
|---------|------|
| 搜索 | 点击搜索按钮触发，回车键也可触发 |
| 重置 | 清空所有搜索条件，重置为第一页 |
| 删除 | 需确认弹窗 |
| 新增/编辑 | 使用对话框或抽屉 |
| 加载 | 列表/详情使用加载状态指示器 |
| 空状态 | 无数据时展示空状态占位 |
| 消息提示 | 操作成功/失败的即时反馈 |

### 3.5 响应式设计策略

| 断点 | 适用设备 | 布局策略 |
|------|---------|---------|
| 大屏（≥1280px） | 桌面端 | 标准多列布局 |
| 中屏（768px-1279px） | 平板/小屏 | 可收缩侧边栏 |
| 小屏（<768px） | 手机 | 单列布局，隐藏次要信息 |

## 四、工作职责

### 4.1 产出UI设计规范（Phase 2）

**输入：** `{{DOC_DIR}}/prd.md`

**产出：** `{{DOC_DIR}}/ui-guide.md`

**内容：**
1. 页面清单（每个功能对应哪些页面）
2. 每个页面的布局设计
3. 交互规范
4. 状态展示规范（各种状态的标签颜色、图标）
5. 表单设计规范（字段布局、校验提示）
6. 响应式策略
7. HTML设计稿（可在浏览器直接预览）

### 4.2 HTML设计稿规范

设计稿必须是**可渲染的HTML文件**，可直接在浏览器中打开预览：

- 使用项目UI框架的CDN版本加载组件
- 包含模拟数据（Mock Data）用于展示
- 页面结构与最终实现保持一致
- 样式使用项目的CSS方案

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>[页面名称] - 设计稿</title>
  <!-- 项目UI框架CDN -->
  <!-- 样式 -->
  <style>
    body { margin: 0; padding: 20px; }
    .page-container { max-width: 1400px; margin: 0 auto; }
  </style>
</head>
<body>
  <div id="app">
    <div class="page-container">
      <!-- 使用UI框架组件编写设计稿 -->
    </div>
  </div>
  <script>
    // Mock数据和初始化
  </script>
</body>
</html>
```

> **具体CDN地址和组件用法参考 `ui-design-system` Skill。**
