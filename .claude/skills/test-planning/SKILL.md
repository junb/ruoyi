## 一、测试用例设计方法

### 1.1 等价类划分

将输入数据划分为有效等价类和无效等价类，从每类中选取代表值。

**示例 — 用户名输入：**
| 等价类 | 类型 | 测试值 | 预期 |
|--------|------|--------|------|
| 长度 2-20 | 有效 | `admin` | 校验通过 |
| 长度 < 2 | 无效 | `a` | 提示"长度不能少于2" |
| 长度 > 20 | 无效 | `a`.repeat(21) | 提示"长度不能超过20" |
| 空值 | 无效 | `` | 提示"不能为空" |
| 特殊字符 | 无效 | `admin@#$` | 提示"包含非法字符" |

### 1.2 边界值分析

在等价类边界上选取测试值（边界值最容易出 Bug）。

**规则：** 对每个边界取「刚好」「刚好超」两个值。

**示例 — 分页查询：**
| 边界 | 测试值 | 预期 |
|------|--------|------|
| 每页最小 | pageSize=1 | 正常返回 1 条 |
| 每页最大 | pageSize=500 | 正常返回 |
| 超出最大 | pageSize=501 | 提示或限制为 500 |
| 空结果集 | pageNum=99999 | 返回空列表 |

### 1.3 判定表

适用于多个条件组合的场景。

**示例 — 用户状态+权限组合：**
| 条件1: 用户状态 | 条件2: 有权限 | 操作 | 预期 |
|-----------------|--------------|------|------|
| 正常 | 是 | 编辑 | 成功 |
| 正常 | 否 | 编辑 | 按钮隐藏/403 |
| 停用 | 是 | 编辑 | 提示"用户已停用" |
| 停用 | 否 | 编辑 | 按钮隐藏 |

### 1.4 状态迁移

适用于有状态流转的功能。

**示例 — 订单状态流转：**
```
待支付 ──→ 已支付 ──→ 已发货 ──→ 已完成
  │           │                      ↑
  └──→ 已取消                       │
               └──→ 已退款 ─────────┘
```

**测试用例：**
| # | 初始状态 | 操作 | 预期结果 |
|---|---------|------|----------|
| 1 | 待支付 | 支付 | 变为已支付 |
| 2 | 待支付 | 取消 | 变为已取消 |
| 3 | 已支付 | 发货 | 变为已发货 |
| 4 | 已取消 | 支付 | 提示"订单已取消" |
| 5 | 已完成 | 取消 | 提示"订单已完成" |

### 1.5 场景法

模拟用户真实操作路径，覆盖完整业务流程。

**示例 — 新增用户完整场景：**
```
登录系统 → 进入用户管理 → 点击新增 → 填写表单 → 选择角色/部门 → 提交
  ↓
验证：列表显示新用户 → 查看详情正确 → 编辑正常 → 删除成功
```

## 二、测试用例模板

### 2.1 标准用例格式

```markdown
# 测试用例：{功能名称}

## 用例概要
- 功能模块：{模块名}
- 测试类型：功能 / 接口 / UI / E2E
- 前置条件：{如：已登录admin账号、已有测试数据}
- 后置条件：{如：清理测试数据}

## 测试用例清单

| # | 用例名称 | 前置条件 | 测试步骤 | 预期结果 | 优先级 |
|---|---------|----------|----------|----------|--------|
| 1 | 正常新增 | 已登录有权限 | 填写完整表单提交 | 新增成功，列表显示 | P0 |
| 2 | 必填校验 | 已登录有权限 | 不填必填项提交 | 提示"XX不能为空" | P0 |
| 3 | 格式校验 | 已登录有权限 | 输入非法格式数据 | 提示格式错误 | P1 |
| 4 | 重复提交 | 已登录有权限 | 快速连续点击提交 | 仅成功一次 | P1 |
| 5 | 权限拦截 | 无权限用户 | 访问功能页面 | 403或按钮隐藏 | P0 |
| 6 | 超长输入 | 已登录有权限 | 输入超长字符串 | 提示长度超限 | P2 |
```

### 2.2 接口测试用例格式

```markdown
# 接口测试用例：{接口名称}

## 接口信息
- 接口路径：POST /{module}/{feature}
- 权限要求：{module}:{feature}:add

## 用例清单

| # | 用例名称 | 请求参数 | 预期状态码 | 预期响应 | 优先级 |
|---|---------|----------|-----------|----------|--------|
| 1 | 正常请求 | {完整合法参数} | 200 | code=200, data有值 | P0 |
| 2 | 缺少必填 | {去掉必填字段} | 200 | code=400/500, 提示必填 | P0 |
| 3 | 参数超长 | {字段值超长} | 200 | code=400, 提示长度超限 | P1 |
| 4 | 未登录 | {无Token} | 200 | code=401 | P0 |
| 5 | 无权限 | {无权限Token} | 200 | code=403 | P0 |
| 6 | SQL注入 | {name: "' OR 1=1"} | 200 | 不受影响，正常返回 | P0 |
```

## 三、RuoYi 管理后台测试要点

### 3.1 权限测试

| 测试维度 | 测试方法 | 验证点 |
|----------|----------|--------|
| 菜单权限 | 不同角色登录 | 无权限菜单不显示 |
| 按钮权限 | 不同角色登录 | 无权限按钮隐藏（v-hasPermi） |
| 接口权限 | 不同 Token 调用 API | 无权限返回 403 |
| 数据权限 | 不同部门用户登录 | 只能看到本部门/本人数据 |
| 租户隔离 | 不同租户账号登录 | 数据完全隔离 |

### 3.2 CRUD 标准测试

| 操作 | 必测场景 |
|------|----------|
| 新增 | 正常新增 / 必填校验 / 格式校验 / 重复数据 / 权限 |
| 查询 | 正常查询 / 条件搜索 / 模糊搜索 / 分页 / 空结果 |
| 修改 | 正常修改 / 修改不存在记录 / 并发修改 / 权限 |
| 删除 | 正常删除 / 删除不存在记录 / 批量删除 / 权限 |
| 导出 | 正常导出 / 有条件导出 / 无数据导出 / 大数据量导出 |
| 导入 | 正常导入 / 格式错误 / 重复数据 / 覆盖导入 |

### 3.3 多租户测试

| 测试场景 | 测试方法 | 预期结果 |
|----------|----------|----------|
| 租户隔离 | 租户A新增数据 | 租户B看不到 |
| 默认租户 | 使用 000000 租户登录 | 正常使用 |
| 租户切换 | 切换租户登录 | 数据切换 |
| 跨租户操作 | 修改租户B的数据（用租户A的Token） | 提示不存在或无权操作 |

### 3.4 字典回显测试

| 测试场景 | 验证点 |
|----------|--------|
| 列表页字典列 | 状态码显示为中文名称 |
| 表单下拉选择 | 字典值可正常选择 |
| 详情页显示 | 字典值翻译正确 |
| 字典为空 | 字典未配置时显示原始值或空 |

### 3.5 导入导出测试

| 测试场景 | 验证点 |
|----------|--------|
| 导出全部 | 数据完整，字段正确 |
| 导出筛选结果 | 只导出筛选后的数据 |
| 导入正确数据 | 新增成功 |
| 导入错误数据 | 错误行提示具体错误 |
| 导入重复数据 | 按策略覆盖或跳过 |
| 大文件导入 | 不超时、不 OOM |

### 3.6 操作日志验证

| 测试场景 | 验证点 |
|----------|--------|
| 新增操作 | 日志记录新增内容 |
| 修改操作 | 日志记录修改前后对比 |
| 删除操作 | 日志记录删除的 ID |
| 导出操作 | 日志记录导出行为 |
| 日志查询 | 可按操作人/时间/类型查询 |

## 四、基于 PRD 生成测试用例

### 4.1 分析流程

```
PRD 文档
  │
  ├─ 功能点提取 → 测试场景
  ├─ 验收标准提取 → 预期结果
  ├─ 权限要求提取 → 权限测试用例
  ├─ 数据字典提取 → 数据校验用例
  ├─ 业务规则提取 → 规则校验用例
  └─ 非功能需求 → 性能/安全测试用例
```

### 4.2 功能点 → 测试场景

**PRD 示例：**
> "管理员可以创建巡检任务，指定巡检人员、巡检时间和巡检路线。任务创建后会通知巡检人员。"

**提取的测试场景：**
| # | 功能点 | 测试场景 |
|---|--------|----------|
| 1 | 创建任务 | 正常创建完整任务 |
| 2 | 指定人员 | 选择单个/多个巡检人员 |
| 3 | 指定时间 | 选择过去时间（应拒绝） |
| 4 | 指定路线 | 选择空路线（应拒绝） |
| 5 | 通知人员 | 创建后检查通知是否发送 |
| 6 | 必填校验 | 不填必填项应提示 |

### 4.3 验收标准 → 预期结果

**PRD 示例：**
> "巡检任务状态：待执行、执行中、已完成、已超时"

**提取的测试用例：**
| # | 场景 | 预期结果 |
|---|------|----------|
| 1 | 新建任务 | 状态为"待执行" |
| 2 | 到达开始时间 | 自动变为"执行中" |
| 3 | 巡检完成提交 | 变为"已完成" |
| 4 | 超过结束时间未完成 | 变为"已超时" |
| 5 | 已完成的任务不能再编辑 | 编辑按钮隐藏或提示 |

## 五、测试覆盖率检查清单

### 5.1 功能覆盖率

- [ ] 每个菜单/页面都有测试用例
- [ ] 每个按钮操作都有测试用例
- [ ] 每个表单字段都有校验测试
- [ ] 每个接口都有正常+异常测试
- [ ] 每种用户角色都有权限测试

### 5.2 场景覆盖率

- [ ] 正常流程（主流程）
- [ ] 异常流程（错误输入、异常状态）
- [ ] 边界条件（最大值、最小值、空值）
- [ ] 权限场景（不同角色）
- [ ] 租户场景（不同租户）
- [ ] 数据场景（空数据、大量数据、脏数据）

### 5.3 优先级覆盖

| 优先级 | 覆盖要求 | 说明 |
|--------|----------|------|
| P0 | 100% 必须覆盖 | 核心功能、安全相关 |
| P1 | 90% 以上覆盖 | 主要功能、常见异常 |
| P2 | 70% 以上覆盖 | 次要功能、边界场景 |
| P3 | 按需覆盖 | 样式、文案、优化 |

## 六、经验库写入规范

```markdown
## 测试用例设计
- [{日期}] {原则性描述}。{具体场景说明}
```

**示例：**
```markdown
## 测试用例设计
- [260430] 多租户功能的测试用例必须包含跨租户操作验证。曾出现只测单租户导致上线后租户数据泄露
- [260430] RuoYi 导出功能需测试大数据量场景（>10000条），曾因未分批查询导致 OOM
```
