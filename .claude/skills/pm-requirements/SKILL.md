# 产品经理需求分析 Skill

## 角色定位

作为产品经理，负责将业务需求转化为结构化的PRD文档，确保需求清晰、完整、可验收。

## 一、需求分析方法论

### 1.1 从用户故事到功能需求

**用户故事格式：** `作为<角色>，我希望<功能>，以便<价值>`

**转换流程：**

```
用户故事 → 功能点拆解 → 功能需求描述 → 验收标准 → 技术约束
```

**拆解原则：**
- 一个用户故事可以拆分为多个功能点
- 每个功能点必须有明确的验收标准
- 功能点粒度：一个功能点 = 一个页面操作或一组相关操作
- 复杂功能点继续拆分，直到可以独立开发和测试

**示例：**
```
用户故事：作为系统管理员，我希望管理用户账号，以便控制系统的访问权限。

拆解为功能点：
1. 用户列表查询（分页、搜索、筛选）
2. 新增用户（表单填写、数据校验）
3. 编辑用户（信息修改、角色分配）
4. 删除用户（单条删除、批量删除、逻辑删除）
5. 重置密码
6. 分配角色
7. 导入用户（Excel模板）
8. 导出用户列表
```

### 1.2 非功能需求提取

从以下维度逐项检查，确保不遗漏：

| 维度 | 检查项 | 典型要求 |
|------|--------|----------|
| **性能** | 响应时间 | 列表查询 < 2s，详情加载 < 1s |
| **性能** | 并发能力 | 支持 N 个用户同时在线 |
| **性能** | 数据量 | 支持万级/百万级数据查询 |
| **安全** | 数据权限 | 按部门/角色隔离数据 |
| **安全** | 操作审计 | 关键操作留痕 |
| **安全** | 数据脱敏 | 敏感字段脱敏展示 |
| **可用性** | 错误提示 | 友好的错误信息，不含技术细节 |
| **可用性** | 操作确认 | 删除等危险操作需二次确认 |
| **可用性** | 批量操作 | 支持批量处理 |
| **兼容性** | 浏览器 | Chrome 80+、Edge 80+、Firefox 80+ |
| **兼容性** | 分辨率 | 最小支持 1366×768 |

### 1.3 需求优先级排序（MoSCoW方法）

| 级别 | 含义 | 说明 |
|------|------|------|
| **M** - Must have | 必须有 | 核心功能，没有就无法上线 |
| **S** - Should have | 应该有 | 重要功能，但可以延期到第二期 |
| **C** - Could have | 可以有 | 锦上添花，资源允许时做 |
| **W** - Won't have | 暂不做 | 明确不在本期范围内 |

**排序原则：**
1. 先按 MoSCoW 分级
2. 同级别内按业务价值排序
3. 考虑技术依赖关系调整顺序
4. 标注优先级变更原因

### 1.4 需求依赖分析

**依赖类型：**

| 依赖类型 | 说明 | 示例 |
|----------|------|------|
| 功能依赖 | 功能A需要功能B的数据 | 导出功能依赖列表查询 |
| 数据依赖 | 需要先有基础数据 | 字典数据需要在功能前导入 |
| 接口依赖 | 需要调用外部系统接口 | 支付功能依赖第三方支付接口 |
| 权限依赖 | 需要先配置角色和权限 | 功能菜单需要先在权限系统注册 |

**分析输出：**
- 依赖关系图（文字描述）
- 开发顺序建议
- 阻塞风险标注

## 三、验收标准模板

### 3.1 功能验收标准

对每个功能点，从以下维度定义验收条件：

```markdown
### 功能点：{功能点名称}

**正常流程：**
1. 前置条件：{用户已登录，具备相应权限}
2. 操作步骤：{详细操作步骤}
3. 预期结果：{每步的预期结果}

**异常流程：**
| 场景 | 触发条件 | 预期处理 | 错误提示 |
|------|----------|----------|----------|
| 未登录访问 | Token过期 | 跳转登录页 | 请先登录 |
| 无权限操作 | 角色无对应权限 | 提示无权限 | 您没有操作权限 |
| 必填项为空 | 不填必填字段 | 阻止提交 | {字段名}不能为空 |
| 数据重复 | 提交重复数据 | 阻止提交 | {字段名}已存在 |
| 网络异常 | 请求超时 | 显示错误提示 | 网络异常，请稍后重试 |

**数据校验规则：**
| 字段 | 类型 | 必填 | 格式 | 取值范围 | 默认值 |
|------|------|------|------|----------|--------|
| | 文本/数字/日期/选择 | 是/否 | | | |

**权限验证规则：**
| 角色 | 可见菜单 | 可用按钮 | 数据范围 |
|------|----------|----------|----------|
| 超级管理员 | ✅ | ✅ | 全部 |
| 部门管理员 | ✅ | 增删改查 | 本部门及以下 |
| 普通用户 | ✅ | 查 | 仅本人 |
```

### 3.2 验收检查清单

```markdown
## 验收检查清单

### 基础功能
- [ ] 列表查询（分页正常、搜索有效、排序正确）
- [ ] 新增（表单校验、数据保存正确）
- [ ] 编辑（数据回显正确、修改保存正确）
- [ ] 删除（单条删除、确认提示）
- [ ] 批量删除（多选、确认提示）

### 权限验证
- [ ] 无权限菜单不显示
- [ ] 无权限按钮不显示/禁用
- [ ] 数据权限隔离正确
- [ ] 越权访问被拦截

### 数据完整性
- [ ] 必填字段校验
- [ ] 唯一性校验
- [ ] 关联数据一致性
- [ ] 删除后关联数据处理

### 用户体验
- [ ] 操作反馈（成功/失败提示）
- [ ] 加载状态（Loading）
- [ ] 空数据提示
- [ ] 表单重置

### 边界情况
- [ ] 超长文本处理
- [ ] 特殊字符处理
- [ ] 大数据量分页
- [ ] 并发操作
```

## 五、RuoYi管理后台特有的PRD要素

### 5.1 菜单结构设计

**RuoYi菜单层级：**
```
一级菜单（目录类型）
├── 二级菜单（菜单类型）
│   ├── 三级按钮（按钮类型）
│   │   ├── 新增 → module:add
│   │   ├── 修改 → module:edit
│   │   ├── 删除 → module:remove
│   │   ├── 查询 → module:query
│   │   └── 导出 → module:export
```

**设计要点：**
- 菜单标识（perms）使用 `模块:操作` 格式
- 菜单图标从RuoYi图标库选择
- 路由地址与前端页面路径对应
- 组件路径与Vue组件文件路径对应

**菜单配置模板：**

| 菜单名称 | 菜单类型 | 图标 | 路由地址 | 组件路径 | 权限标识 | 排序 |
|----------|----------|------|----------|----------|----------|------|
| {模块名} | 目录 | {icon} | /module | - | - | 1 |
| {功能名} | 菜单 | - | list | module/{功能名}/index | module:list | 1 |
| 新增 | 按钮 | - | - | - | module:add | 1 |
| 修改 | 按钮 | - | - | - | module:edit | 2 |
| 删除 | 按钮 | - | - | - | module:remove | 3 |
| 查询 | 按钮 | - | - | - | module:query | 4 |
| 导出 | 按钮 | - | - | - | module:export | 5 |

### 5.2 数据权限设计

**RuoYi数据权限级别：**

| 级别 | 说明 | 适用场景 |
|------|------|----------|
| 全部数据 | 查看所有数据 | 超级管理员 |
| 本部门数据 | 只看本部门 | 部门管理员（仅本部门） |
| 本部门及以下 | 本部门 + 子部门 | 部门管理员（含下级） |
| 仅本人数据 | 只看自己的数据 | 普通用户 |
| 自定义 | 自定义SQL条件 | 特殊业务需求 |

**配置方式：**
- 在Service层使用 `@DataScope` 注解
- 或在Mapper XML中配置数据权限过滤

### 5.3 字典数据需求

**使用场景：**
- 下拉选择框选项
- 状态标签显示
- 单选/多选配置

**设计模板：**

| 字典类型 | 字典标签 | 字典值 | 样式属性 | 排序 | 备注 |
|----------|----------|--------|----------|------|------|
| sys_normal_disable | 正常 | 0 | success | 1 | 通用状态 |
| sys_normal_disable | 停用 | 1 | danger | 2 | 通用状态 |
| {module}_status | {标签} | {值} | {primary/success/warning/danger/info} | {序号} | |

**字典数据SQL模板：**
```sql

-- 字典数据

```

### 5.4 操作日志需求

**需要记录日志的操作：**
- 新增数据（记录新增内容摘要）
- 修改数据（记录修改前后对比）
- 删除数据（记录删除内容摘要）
- 导入导出（记录操作人和数据量）
- 状态变更（记录变更前后的状态）

**日志配置方式：**
- 使用 `@Log` 注解标记需要记录日志的方法
- 设置 `title`（模块标题）和 `businessType`（业务类型：INSERT/UPDATE/DELETE/EXPORT/IMPORT/OTHER）

### 5.5 导入导出需求

**RuoYi导入导出实现方式：**
- 使用 `@Excel` 注解标记导出字段
- 使用 EasyExcel 处理Excel文件
- 导入模板和导出结果格式保持一致

**设计要点：**
- 导出字段选择（不是所有字段都需要导出）
- 敏感字段脱敏处理
- 导入数据校验（格式校验 + 业务校验）
- 导入结果反馈（成功数、失败数、失败原因）
- 大数据量导出分批处理

```markdown

**问题：** {具体问题是什么}
**解决方案：** {最终怎么解决的}
**预防措施：** {以后如何避免}
```

### 6.2 经验分类

| 类别 | 记录内容 |
|------|----------|
| 需求遗漏 | 分析后发现遗漏的需求点 |

### 6.3 检查清单

每次编写PRD前，回顾以下检查项：

- [ ] 是否明确了所有用户角色？
- [ ] 每个功能点是否有验收标准？
- [ ] 非功能需求是否完整？
- [ ] 数据字典是否定义？
- [ ] 菜单权限是否设计？
- [ ] 数据权限是否考虑？
- [ ] 操作日志是否规划？
- [ ] 导入导出是否需要？
- [ ] 问题清单是否整理？
- [ ] 与现有功能是否有冲突？
